Introduction#

What are Bayesian Network Classifiers?#

Bayesian Network Classifiers (BNCs) compute class probabilities using Bayes’ theorem. The most common is Naive Bayes, which assumes features are conditionally independent given the class:

\[P(y|\mathbf{x}) \propto P(y) \prod_{i=1}^{n} P(x_i|y)\]

This assumption is rarely true, but Naive Bayes scales well and works as a baseline. When feature dependencies are strong (e.g., in a parity problem like XOR), it produces inaccurate probabilities.

Why scikit-bayes?#

While scikit-learn includes standard Naive Bayes classes, they require some manual workarounds for complex datasets:

  1. Heterogeneous data: You cannot pass a matrix with Gaussian, Categorical, and Bernoulli features directly into a single estimator without using a ColumnTransformer to split them.

  2. Feature dependencies: There are no out-of-the-box implementations of n-dependence estimators like AODE or A2DE.

  3. Hybrid optimization: Scikit-learn does not implement discriminatively-weighted Bayesian classifiers like ALR, which use generative models as preconditioners.

scikit-bayes implements these architectures while passing standard scikit-learn estimator checks.

MixedNB: Mixed Data Naive Bayes#

skbn.MixedNB handles datasets with heterogeneous feature types by internally combining scikit-learn’s specialized Naive Bayes estimators.

The Problem#

Consider a dataset with:

  • Feature 0: Age (continuous) → Gaussian

  • Feature 1: Gender (binary) → Bernoulli

  • Feature 2: Education Level (0, 1, 2, 3) → Categorical

With sklearn, you’d need to:

  1. Split features by type

  2. Fit separate NB classifiers

  3. Combine probabilities manually

MixedNB does this automatically.

Feature Type Detection#

MixedNB auto-detects feature types during fit():

  • Gaussian: Float features with non-integer values

  • Bernoulli: Features with exactly 2 unique values

  • Categorical: Integer features with >2 unique values

You can also specify types manually:

from skbn import MixedNB

# Force features 2 and 3 to be categorical
clf = MixedNB(categorical_features=[2, 3])

# Force feature 1 to be Bernoulli
clf = MixedNB(bernoulli_features=[1])

Usage Example#

import numpy as np
from skbn import MixedNB

# Features: [Gaussian, Bernoulli, Categorical]
X = np.array([
    [1.5, 0, 0],
    [2.3, 1, 1],
    [0.8, 1, 2],
    [1.1, 0, 0],
    [3.2, 1, 1],
    [-0.5, 0, 2]
])
y = np.array([0, 1, 1, 0, 1, 0])

clf = MixedNB(alpha=1.0)
clf.fit(X, y)

# Inspect detected types
print(clf.feature_types_)
# {'gaussian': [0], 'bernoulli': [1], 'categorical': [2]}

# Predict
print(clf.predict([[1.0, 1, 1]]))  # [1]
print(clf.predict_proba([[1.0, 1, 1]]))  # [[0.xx, 0.xx]]

Parameters#

  • alpha: Smoothing parameter (Laplace smoothing) for Categorical/Bernoulli. Default: 1.0

  • var_smoothing: Variance smoothing for Gaussian features. Default: 1e-9

  • categorical_features: List of indices to treat as categorical

  • bernoulli_features: List of indices to treat as Bernoulli

AnDE Family: Relaxing Independence#

The Averaged n-Dependence Estimators (AnDE) family relaxes the independence assumption by conditioning on “super-parent” features.

The Independence Problem#

Consider the XOR problem:

X2

-1

-1

0

-1

+1

1

+1

-1

+1

0

Looking at X1 alone: P(X1|Y=0) = P(X1|Y=1) (symmetric distributions). Looking at X2 alone: P(X2|Y=0) = P(X2|Y=1) (symmetric distributions).

Naive Bayes cannot learn this. It achieves ~50% accuracy (random guessing).

AnDE solves this by modeling P(X2 | Y, X1) instead of just P(X2 | Y).

The Super-Parent Strategy#

An SPnDE (Super-Parent n-Dependence Estimator) conditions all child features on the class and n parent features:

\[P(y, \mathbf{x}) = P(Y^*) \prod_{i \in children} P(x_i | Y^*)\]

Where \(Y^* = (y, x_{p1}, x_{p2}, ..., x_{pn})\) is the “augmented super-class”.

AnDE averages over all possible parent combinations.

AnDE (Arithmetic Mean)#

skbn.AnDE is the standard generative model described by Webb et al. [1].

\[P(y|\mathbf{x}) \propto \sum_{m} P_m(y, \mathbf{x})\]

Key Parameters:

  • n_dependence: Order of dependence

    • n=0: Equivalent to Naive Bayes (MixedNB)

    • n=1: AODE (Averaged One-Dependence Estimators)

    • n=2: A2DE (common choice for higher accuracy)

  • n_bins: Discretization bins for continuous super-parents

  • strategy: Discretization strategy (‘uniform’, ‘quantile’, ‘kmeans’)

Example:

from skbn import AnDE

# AODE (n=1)
clf = AnDE(n_dependence=1, n_bins=5)
clf.fit(X, y)

# A2DE (n=2) - higher accuracy, more computation
clf = AnDE(n_dependence=2, n_bins=5)

With mean="geometric" the components are pooled with the geometric mean, \(P(y|\mathbf{x}) \propto \prod_{m} P_m(y, \mathbf{x})^{1/|M|}\). Every component then counts the same, so a few components that give a class a probability close to zero rule it out. This pool of SPnDEs is not the AnJE of Zaidi et al. [4], which is described below.

WeightedAnDE#

skbn.WeightedAnDE learns discriminative weights on top of AnDE by maximising the conditional log-likelihood with L-BFGS-B. The weights start at, and are regularized towards, the generative model (w = 1). Two parameters define the model:

  • mean: how the components are pooled ("arithmetic" or "geometric").

  • weight_scope: what each weight multiplies.

    • "component": a whole SPnDE. With the arithmetic mean the weights are mixture coefficients, \(\log \sum_m w_m P_m(y, \mathbf{x})\); with the geometric mean they scale the log-joints, \(\sum_m w_m \log P_m(y, \mathbf{x})\).

    • "factor": every factor of every SPnDE, as in the weighted CCBN of Zaidi et al. [3]: \(P_m^w = \prod_f \theta_f^{w_f}\).

weight_level sets the variables that index each weight:

Level

Component Weights

Factor Weights [3]

1

Component

Factor

2

Component × parent value

Factor × value

3

Component × class

Factor × value × class

4

Component × class × parent value

Factor × value × class × parents

The factor levels are the nested parameterizations of Zaidi et al. [3] (Sec. 5.4), applied inside each SPnDE. Arithmetic component weights at level 3 are the per-SPODE, per-class weights of EODE-CLL [5]. The other component levels follow the same nesting at the level of the component; they are a choice of this library, not of the literature.

Component weights are cheap (one weight per component and sample) but only decide how much each SPnDE is trusted: they cannot correct a dependence between children that every SPnDE shares, such as a duplicated attribute. Factor weights can, at the cost of about n_features times more weights. With the geometric mean, and with modular=True (each component fitted on its own conditional log-likelihood), the objective is convex.

average decides what the arithmetic mean pools: the weighted joints \(P^w_m(y, \mathbf{x})\), as AnDE does ("joint", the default), or the components’ posteriors \(P^w_m(y | \mathbf{x})\) ("posterior"). The two coincide for the geometric mean. Factor weights at level 4, fitted with modular=True and pooled with average="posterior", are the AnDEw of FedAnDE: one weighted CCBN per SPnDE, trained on its own data and averaged, which is what lets each component be fitted across sites.

from skbn import WeightedAnDE

# One weight per SPODE and class
clf = WeightedAnDE(n_dependence=1, weight_level=3)

# Weighted CCBN inside each SPODE
clf = WeightedAnDE(n_dependence=1, weight_scope="factor", weight_level=3)

# AnDE^w of FedAnDE
clf = WeightedAnDE(
    n_dependence=1, weight_scope="factor", weight_level=4,
    modular=True, average="posterior",
)
clf.fit(X, y)

AnJE and ALR#

skbn.AnJE and skbn.ALR follow Zaidi et al. [4]. Instead of SPnDEs they use n-joins, the joint distributions \(P(x_\alpha | y)\) of every subset \(\alpha\) of n_join attributes. AnJE pools them with the geometric-mean weight of the paper:

\[P(y|\mathbf{x}) \propto P(y) \prod_{\alpha} P(x_\alpha | y)^{\frac{(n-1)!(a-n)!}{(a-1)!}}\]

ALR (ALRn in the paper) learns one weight per n-join, value and class by maximising the conditional log-likelihood, a convex problem:

\[\log P(y|\mathbf{x}) = w_y \log P(y) + \sum_{\alpha} w_{y,\alpha,x_\alpha} \log P(x_\alpha | y) - \log Z(\mathbf{x})\]

A1JE is Naive Bayes, and AnJE uses the same statistics as A(n-1)DE, so AnJE(n_join=2) is comparable to AnDE(n_dependence=1). Both models are defined on discrete attributes: continuous attributes are discretized into n_bins bins (the paper uses MDL discretization, available as skbn.MDLPDiscretizer). Probabilities are m-estimates with m = alpha.

weight_level=3 (the default) is the model of the paper. Levels 1 (one weight per n-join) and 2 (per n-join and value) tie the weights following the nesting of [3]. The other defaults reproduce the protocol of the paper’s experiments: weights start at w = 1, there is no penalty, and L-BFGS-B runs until the relative reduction of the objective falls below 1e-32 or for 104 iterations. The starting point is not the AnJE but the unaveraged product of all n-joins, so on small samples the unpenalized model overfits. l2_reg adds the penalty towards w = 1 that the paper suggests for small datasets, and max_iter and tol stop the optimizer earlier.

from skbn import ALR, AnJE

clf = AnJE(n_join=2)
clf = ALR(n_join=2)  # as in Zaidi et al. (2016)
clf.fit(X, y)

TAN: Tree Augmented Naive Bayes#

skbn.TAN [6] relaxes the independence assumption in a different way from AnDE: instead of averaging many models, it learns a single network in which every attribute has the class and at most one other attribute as parents.

\[P(y, \mathbf{x}) = P(y) \, P(x_r | y) \prod_{i \neq r} P(x_i | y, x_{\pi(i)})\]

Where \(r\) is the root of the tree and \(\pi(i)\) the parent of attribute \(i\).

Learning the Tree#

The structure is learned with the Chow-Liu procedure [7]:

  1. Compute the conditional mutual information \(I(A_i; A_j | C)\) between every pair of attributes.

  2. Build the maximum weight spanning tree of the complete graph with these weights.

  3. Choose a root (root) and direct every edge away from it.

The choice of root does not change which attributes are connected, only the direction of the edges.

Mixed Data#

TAN uses the same strategy as the AnDE family. Continuous attributes are discretized (n_bins, strategy) to compute the mutual information and when they act as parents; as children they remain continuous and are modeled by Gaussian distributions. Every conditional \(P(x_i | y, x_{\pi(i)})\) is a skbn.MixedNB fitted on the augmented class \((y, x_{\pi(i)})\), so discrete children use Laplace smoothing (alpha).

Key Parameters:

  • root: Index of the root attribute. Default: 0

  • alpha: Laplace smoothing for discrete attributes. Default: 1.0

  • n_bins: Discretization bins for continuous attributes

  • strategy: Discretization strategy (‘uniform’, ‘quantile’, ‘kmeans’)

Example:

from skbn import TAN

clf = TAN()
clf.fit(X, y)

clf.parents_                   # parent of each attribute (-1 for the root)
clf.conditional_mutual_info_   # edge weights used to learn the tree

Parameter Tuning Guide#

Choosing n_dependence#

  • n=1 (AODE): Good default. Captures pairwise interactions.

  • n=2 (A2DE): Better accuracy, but O(n²) models. Use for <50 features.

  • n≥3: Rarely needed. Computational cost grows combinatorially.

Discretization Strategy#

For continuous super-parents:

  • ‘quantile’ (default): Equal-frequency bins. Robust to outliers.

  • ‘uniform’: Equal-width bins. Good for uniform distributions.

  • ‘kmeans’: Data-driven bins. Best for multi-modal distributions.

n_bins typically 3-10. More bins = more precision but fewer samples per bin.

Regularization in Hybrid Models#

l2_reg is the strength of the penalty \(\lambda \|\mathbf{w} - 1\|^2\) added to the summed conditional log-likelihood, so its effect weakens as the training set grows. The default of skbn.WeightedAnDE is 1.0. Component weights are few and barely react to it; factor weights are many and overfit small datasets with a weak penalty, so for them values between 0.1 and 10, chosen by cross-validation, are the safe range.

Computational Considerations#

  • Use n_jobs=-1 to parallelize SPODE fitting

  • The cost of an optimization step grows with the number of weights each sample touches: one per component with component weights, one per factor with factor weights and one per n-join in ALR

  • A2DE with n_features=50 creates ~1,225 sub-models
